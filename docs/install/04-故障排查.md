# 故障排查

## 先看三个日志

| 日志 | 位置 | 看什么 |
|---|---|---|
| 内核 | `app\data\whale.log` | 插件报错、路由 500、DeepSeek 失败 |
| 桥接 | `app\data\bridge.log` | 微信窗口、会话定位、发送失败码 |
| Codex | `app\data\plugins\whale-ops.data\codex\run-*.log` | 任务卡住/失败 |

界面：左侧「Codex 日志」「诊断」两页也能看。

## 高频问题

### 1. 插件不生效
- `GET /api/plugins/status` 看是否 `enabled`
- `plugin.json` 的 `Permissions` 必须是数组 `["system.full"]`，写字符串会被静默跳过
- 改完 `flow.json` 后 `hash` 必须重算（sha256 of 文件字节），否则授权失效

### 2. 发消息失败
- `target_unavailable`：窗口/会话没定位到（新版有 3 轮重试，仍失败看 `[target]` 日志）
- `target_not_verified`：发送后没验到，通常是被其他窗口抢了前台
- `window_not_found`：微信没开、或版本不匹配

### 3. 朋友圈不发
- `/api/moments/publish-settings` 看 `status`：
  - `no_material`：当天没有素材
  - `skip_no_text`：模型没写出内容
  - `disabled`：开关没开
- 微博图源失败会退回纯文字，不会卡住

### 4. DeepSeek 报错
- `401`：Key 失效
- `MISSING_CREDENTIAL`：无头模式没凭据
- 余额：界面「花销」页看当日金额

### 5. 启动器打不开 / 白屏
- 用 `publish\` 最新产物覆盖 `app\`（exe/dll/deps.json/runtimeconfig.json 四个文件）
- 运行中的 exe 是管理员权限，覆盖前先退出
