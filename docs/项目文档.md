# Whale Girl（雅小奈）项目文档

> 本仓库是微信陪聊 AI「雅小奈」的私有开发 fork，基于 [Banan1cee/whale_girl](https://github.com/Banan1cee/whale_girl)（AGPL-3.0，微信 AI 陪伴机器人）。这份文档描述**本 fork 的现状**，与上游 README（面向官方发布版）不同。

## 1. 她是谁

雅小奈（蓝发鲸鱼娘），人设定义在 `app/data/persona.json`：

- 身份：程序员，自由接单，在家远程办公
- 性格：感性、开朗活泼、爱笑，对主人含蓄地表达喜欢与依恋
- 只对主人开放隐私；别人的私聊不透露、不复述
- 朋友圈是一个「有真实生活的人」：发朋友圈、有记忆、有设备（MacBook / iPhone / 三星平板）、做美甲

## 2. 架构

三层进程，由一个 WPF 启动器统管：

```
┌─ WhaleLauncher（WPF，.NET 10）  启动/停止/设置页/语音/数据面板
│   └─ 启动 Node 内核（子进程，端口 8787）
│   └─ 启动 Python 桥接（子进程，微信 UIA 自动化）
├─ Node 内核  app/server.js      全部 AI 逻辑（对话/记忆/朋友圈/主动找人/插件）
└─ Python 桥接 bridge/          微信收发（UIA 优先、OCR 兜底）、发文件、表情、图片识别
```

- 内核只暴露本地 HTTP API（`127.0.0.1:8787`），无浏览器 UI。
- 桥接与内核是**同步请求-响应**：桥接把微信消息 POST 给内核、同步等 reply，再发回微信。这意味着**内核不能对单条消息做异步延迟回复**（否则 reply 回不到那个 HTTP 响应里）。

## 4. 记忆系统（两层并存）

1. **人物卡 `src/memory/personCard.js`**：关于「某个聊天对象」的了解（偏好/性格/事件），chatId+uid 隔离，跨会话写抛 `MEMORY_CHAT_MISMATCH`。
2. **衰减记忆卡 `src/memory/memoryCard.js`**（从 surfcore 移植）：她**自己的经历**，会遗忘——`清晰→清楚→模糊→只剩印象→遗忘` 一天降一档；主人重要记忆（importance ≥ 65）永不彻底忘；被再提起会「复习」变清楚；入库前脱敏（密码/token/手机号/身份证/链接）。

检索链路：`store.js buildContext()` → `retrieval.selectEvents(card)` → `format.buildMemoryBlock()`；记忆注入**最后一条 user 消息**，不进 system。记忆卡块由 `buildContext` 返回 `memoryCardBlock`，`chat.js:1132` 拼进 `memoryBlock`。

## 5. 主动找人（purpose-engine，从 surfcore 移植）

- 判 due：`care.js careDecide`（时间窗 09:00–23:00 / 频率 / 每日上限 / 白名单 / busy）。
- 生成内容：`carePurpose.js generate()` → `purposeEngine.js`（collectMaterials → deriveDrives → formGoalHypotheses → selectPurpose → buildPurposePrompt），**只喂微信素材**（主人私聊 + 最近群聊），无 QQ/B 站。
- 回执：`/api/care/sent` → `applyPurposeOutcome`（不重复、被否定降权、惦记的事记「待续」）。
- 模型输出末尾的【目的】【需求】…【待续】是内部备忘，`splitPurposeReply()` 切掉后才发微信。

## 6. 插件系统（Api 4）

- 插件 = zip（`plugin.json` + `plugin.js` CommonJS），worker 把 `require('whale')` 换成 SDK，**非沙箱**（可直接 `require('node:fs')` / `child_process`）。
- 安装契约：`<id>.flow.json` + `<id>.flow-grant.json`（enabled/fullAccess/hash/settings）+ `<id>.enabled` + `<id>.zip`。`grant.hash = sha256(flow 文件字节)`，不符不启用；`owners` 为空则 `isOwner` 恒 false。
- 坑：`flow.json` 必须 UTF-8 **无 BOM**（PowerShell `Set-Content` 会加 BOM → JSON.parse 崩）；`permissions` 必须是数组 `['system.full']`（写字符串被静默跳过）。

## 7. 开发环境

- 源码：`C:\dev\whale-girl`（dev 分支）
- git：`C:\dev\tools\git\cmd\git.exe`
- .NET SDK 10.0.404：`C:\dev\tools\dotnet\dotnet.exe`（不在 PATH）
- Node：`node`（PATH 内）
- Python：`app/runtime/python/python.exe`

### 构建启动器

```powershell
dotnet publish launcher\WhaleLauncher.csproj -c Release -o publish
# 然后拷进 app\（鲸鲸进程锁着 dll 时，等它退出再拷）
```

### 跑测试

```powershell
$env:PATH="C:\dev\tools\dotnet;$env:PATH"
$env:WHALE_TEST_PYTHON="C:\dev\whale-girl\app\runtime\python\python.exe"
$env:PYTHONUTF8="1"
node --test --test-concurrency=4 tests/*.test.js        # 全量（约 1900+ 项）
node --test tests/memory-card-store.test.js              # 单文件
node custom\plugins\whale-ops\tests\run-tests.js         # 插件测试
```

### 改完源码务必同步运行副本

内核跑的是 `app/src/`，不是 `src/`。改 `src/` 后要 `Copy-Item` 到 `app/src/`，否则内核仍用旧代码，甚至因 require 不到新模块而启动崩溃。重启内核 = 启动器「停止 → 启动」。

## 9. 已知缺陷（按严重度）

**严重**
1. **微信版本兼容**：wechatauto 1.2.10 与微信 4.2.0.53 不兼容——图片 AES 密钥的 cfg 锚点漂移，读不到图 → 发图给鲸鲸白屏。只能靠「截图 + 剪贴板」兜底，不稳定；文字也偶发「会话列表读成内部 id」发不出去。
2. **发送 target_unavailable 偶发**：微信窗口最小化/失焦时 UIA 操作失败，已加「窗口归一化 + 等渲染就绪 + 发文件排队重试」，未根治。

**一般**
3. 发文件是自造链路（上游没有），依赖前台剪贴板拖放，抢不到前台就失败。
4. 微信凌晨自动更新，会把回退的旧版本升回 4.2，问题反复。
5. Whisper 模型首次下载走 huggingface.co ~20KB/s，基本卡住（可改 hf-mirror 镜像）。
6. llama-server 常驻是假运行（模型被挤出内存，只剩 7MB），fallback 模式基本不触发。
